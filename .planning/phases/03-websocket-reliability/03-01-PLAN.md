Create `src/services/wsManager.ts` as a new file implementing the WebSocketManager class per D-01 through D-12. The class must:

**Imports:**

```typescript
import type { WsStatus } from '../types';
```

**Constants (module-level):**

```typescript
const API_KEY = import.meta.env.VITE_TWELVEDATA_API_KEY as string;
const WS_URL = `wss://ws.twelvedata.com/v1/quotes/price?apikey=${API_KEY}`;

const INITIAL_DELAY_MS = 1_000;
const MAX_DELAY_MS = 30_000;
const JITTER_MS = 1_000;
const MAX_ATTEMPTS = 10;
const HEARTBEAT_INTERVAL_MS = 10_000;
const PONG_TIMEOUT_MS = 5_000;
```

**Types (exported from this file since they are WS-specific, not shared domain types):**
```typescript
export type RibbonTickUpdate = { symbol: string; price: number; timestamp: number };
export type WsCallback = (update: RibbonTickUpdate) => void;
export type StatusCallback = (status: WsStatus) => void;
```

**Class private state (per D-04, D-09):**
- `ws: WebSocket | null = null`
- `status: WsStatus = 'disconnected' as WsStatus` — NOTE per D-08: The initial field value must NOT be `'connecting'`. D-08 specifies `'connecting'` only when `connect()` is first called. Use a sentinel value that is NOT in the WsStatus union to represent the pre-connection state. However, since WsStatus does not include a `'disconnected'` value and adding one would change the type contract, instead initialize as `status: WsStatus = 'connecting'` BUT document that the `connect()` guard (checking `ws?.readyState`) prevents double-connect. The `onStatusChange()` method immediately calls `cb(this.status)` — consumers registering before `connect()` will receive `'connecting'`, which is acceptable because `subscribe()` implicitly calls `connect()`, so there is no practical window where a consumer observes `'connecting'` without a connection attempt in progress. Document this design choice in a code comment: `// Per D-08: 'connecting' is the initial state. subscribe() calls connect() implicitly, so consumers always see 'connecting' with a connection attempt in flight.`
- `attempt = 0`
- `reconnectTimer: ReturnType<typeof setTimeout> | null = null`
- `heartbeatTimer: ReturnType<typeof setInterval> | null = null`
- `pongTimer: ReturnType<typeof setTimeout> | null = null`
- `lastPrices: Record<string, number> = {}`
- `prevPrices: Record<string, number> = {}`
- `tickCallbacks: Set<WsCallback> = new Set()`
- `statusCallbacks: Set<StatusCallback> = new Set()`

**Public methods:**

1. `connect(): void` — Per D-01, D-08:
   - Guard: if `ws?.readyState === WebSocket.CONNECTING || ws?.readyState === WebSocket.OPEN` return immediately (pitfall 5 protection)
   - Set status to `'connecting'`, notify status callbacks
   - Create `new WebSocket(WS_URL)`
   - `onopen`: clear reconnectTimer (pitfall 2), reset `attempt = 0` (D-04, D-06), set status `'connected'`, notify callbacks, send subscribe message `{ action: 'subscribe', params: { symbols: WS_SYMBOLS.join(',') } }`, call `startHeartbeat()`
   - `onmessage`: call `clearPongTimer()` first (any message proves liveness — anti-pattern from research). Then parse JSON, if `msg.event === 'price' && msg.symbol && msg.price != null`, update prices: `prevPrices[sym] = lastPrices[sym] ?? price; lastPrices[sym] = price;`, then notify tick callbacks with `{ symbol: sym, price, timestamp: Date.now() }`. Wrap in try/catch with empty catch (matches existing pattern).
   - `onclose`: call `stopHeartbeat()` first (pitfall 3). If `tickCallbacks.size === 0` return without reconnecting (anti-pattern: reconnecting with no subscribers). If `attempt >= MAX_ATTEMPTS` (10), set status `'failed'`, notify, return (D-05, WS-02). Otherwise set status `'reconnecting'`, notify, increment `attempt`, schedule reconnect via `reconnectTimer = setTimeout(() => this.connect(), this.nextDelay())`.
   - `onerror`: just call `ws?.close()` — do NOT schedule reconnect here (pitfall 1: double-reconnect). The `onclose` handler fires automatically after `onerror`.

2. `subscribe(cb: WsCallback): () => void` — Per D-10:
   - Add cb to tickCallbacks
   - Call `this.connect()` (implicit connect per research open question 2 — matches existing subscribeWebSocket behavior)
   - Return unsubscribe function that removes cb from Set, and if Set is now empty calls `this.disconnect()`

3. `onStatusChange(cb: StatusCallback): () => void` — Per D-07:
   - Add cb to statusCallbacks
   - Immediately call `cb(this.status)` so consumer gets current state
   - Return unsubscribe function removing cb from Set

4. `getPrice(symbol: string): number | undefined` — Per D-09: return `this.lastPrices[symbol]`

5. `getPrevPrice(symbol: string): number | undefined` — Per D-09: return `this.prevPrices[symbol]`

6. `reconnect(): void` — Per D-05:
   - Reset `attempt = 0`
   - Set `ws = null` (clear stale reference)
   - Call `this.connect()`

7. `disconnect(): void` — Per D-02:
   - Call `stopHeartbeat()` (pitfall 3)
   - Clear `reconnectTimer` if set
   - If `ws`, call `ws.close()`, set `ws = null`

**Private methods:**

8. `private nextDelay(): number` — Per D-03:
   - `const base = Math.min(INITIAL_DELAY_MS * Math.pow(2, this.attempt - 1), MAX_DELAY_MS);`
   - `const jitter = Math.random() * JITTER_MS;`
   - `return base + jitter;`

9. `private setStatus(newStatus: WsStatus): void`:
   - `this.status = newStatus; this.statusCallbacks.forEach(cb => cb(newStatus));`

10. `private startHeartbeat(): void` — Per D-11, D-12:
    - Call `stopHeartbeat()` first
    - `this.heartbeatTimer = setInterval(() => { if (this.ws?.readyState === WebSocket.OPEN) { this.ws.send(JSON.stringify({ event: 'heartbeat' })); this.pongTimer = setTimeout(() => this.handleSilentDrop(), PONG_TIMEOUT_MS); } }, HEARTBEAT_INTERVAL_MS);`

11. `private stopHeartbeat(): void`:
    - Clear heartbeatTimer and pongTimer, set both to null

12. `private clearPongTimer(): void`:
    - Clear pongTimer if set, set to null

13. `private handleSilentDrop(): void`:
    - Call `this.ws?.close()` — this triggers onclose which handles reconnection

**Singleton export (per D-01):**
```typescript
export const wsManager = new WebSocketManager();
```

IMPORTANT anti-patterns to avoid:
- Do NOT schedule reconnect in onerror — only in onclose (pitfall 1)
- Do NOT start heartbeat before onopen fires
- Do NOT reconnect if tickCallbacks is empty (no subscribers)
- Do NOT export the class constructor for direct instantiation — only export the singleton instance and the class itself for type usage
