Update every fetch callback in `useMarketData.ts` to unwrap DataResult instead of using try/catch for normal flow. Per research Pattern 5, the new pattern is:

```typescript
const result = await getServiceFunction();
if (result.status === 'error') {
  setStatus('widgetKey', errorStatus(result.error));
  return;
}
setData(prev => ({ ...prev, field: result.data }));
setStatus('widgetKey', loadedStatus);
```

Keep a top-level try/catch as a safety net for truly unexpected infrastructure errors (fetch API crash, etc.), but DataResult errors are handled via status narrowing, not catch blocks.

**Add a `warnedStatus` helper** for partial success (per Pitfall 3 in research):
```typescript
function warnedStatus(warnings: ResultWarning[]): WidgetStatus {
  return { state: 'loaded', error: warnings.map(w => w.message).join('; ') };
}
```
Note: This reuses the existing WidgetStatus shape with `state: 'loaded'` but populates the optional `error` field with warning text. Phase 5 (UI-02) will add distinct visual treatment. For now, widgets display data normally but the warning info is available.

const fetchCalendar = useCallback(async () => {

  const [calResult, fomcResult] = await Promise.all([
    getFinnhubEconomicCalendar(),
    getFinnhubFedWatch(),
  ]);

  const fomcData = fomcResult.status === 'ok' ? fomcResult.data : null;

  if (fomcResult.status === 'error') warnings.push({ field: 'fomc', message: fomcResult.error });

    setStatus('calendar', errorStatus(warnings.map(w => w.message).join('; ')));

    ...(calData && { economicCalendar: calData }),
    ...(fomcData && { fomc: fomcData }),
  }));
  setStatus('calendar', warnings.length ? warnedStatus(warnings) : loadedStatus);
